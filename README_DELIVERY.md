# 知微 · 证据问答工作台交付说明

本轮新增：**LoRA 合并（CPU，未量化来源）→ GGUF 转换（f16 + Q4_K_M）→ 本地 llama-server 推理 → 接入现有工作台**。默认后端已切换为 llama.cpp，Transformers + PEFT 保留为回退。冻结对齐用例在两种后端下结果逐格一致，其中“食品安全四步骤”真实触发了一次 JSON 语法受约束重试。全部路径、版本、哈希、显存与限制见同目录 `LLAMACPP_GGUF_REPORT.md`。

评测升级：把“关键词初筛”换成 **span 级证据金标准**——110 例（70 可答 / 40 拒答）逐句标注证据，算选句严格/宽松精确率、召回、误拒率、漏拒率与 Wilson 区间，并在 llama.cpp 与 Transformers 两个后端上对“候选范围 × 排序方式 × 选句模式”做同指标对照。结论：**窄候选精确率最高**（候选从 20 句扩到全语料 343 句，严格精确率 0.802→0.463、`exact` 41/70→3/70）；**交叉编码重排是负面结果**（机制是选择器依赖候选编号而非句子内容）；**拒答短板已按阈值扫描修掉最省的一档**（缺省 0.45→0.48，漏拒 13/40→10/40 且零新增误拒，剩下 7 例定为语义问题）；**微调的价值在拒答与召回**（漏拒 2/40、召回 0.946 更高，代价是严格精确率与 padding）。**上一版基于 54 例得到的“跨文档引用为 0”“拒答方向干净”两条结论已被扩样本推翻**，旧子集在本轮产物里逐字复现，可证明差异来自新增题而非环境漂移。**下表的历史指标不能再作为当前口径引用。** 详见 `EVALUATION_SPAN_REPORT.md`。

## 启动与展示

启动分两步：先起两个本地 `llama-server`（`:8080` 合并模型、`:8081` 基础模型），逐个 `/health` 就绪检测通过后再启动工作台。完整命令见 [`README.md`](README.md) 第四节；本地开发机上另有 PowerShell 一键入口完成同样的顺序，端口被其他进程占用时直接报错，不会去结束别人的进程。

打开 http://127.0.0.1:7860 。回退到 Transformers + PEFT 后端时不需要 llama-server，设 `RAG_GENERATOR_BACKEND=transformers` 后同样启动即可。

建议三分钟演示流程：

1. 在“文档知识库”展示来源、章节、更新时间和原文哈希。6 份 CDC 健康科普文档、67 个段落；另外保留 1 份明确标注的上传验收合成文档（不属于评测语料）。
2. 提问“成年人每天应该刷牙几次？”，再追问“那每年要检查几次？”。查看历史补全后的检索问题。
3. 展开“摘录来源段落”，点击引用，核对中文导读及官方来源。中文导读是人工整理，非官方译文；英文原文也已入库。
4. 展开模型原始输出，说明当前保守检查失败时采用资料摘录保底。保底有独立标签，不冒充模型生成。
5. 打开“独立评测”，展示四种模式的实际差异。最后查看 http://127.0.0.1:7860/docs 接口说明。

## 实际评测结果

冻结的 16 题包括 12 道可答题、4 道无答案题，另有 4 组两轮追问。6 份文档未用于 v4 微调。测试规模小，不能代表整体医学能力。

|模式|原始回答关键点初筛|原始回答有效引用编号|无答案处理|资料摘录保底|
|---|---:|---:|---:|---:|
|原模型|2/12|0/12|0/4|0/12|
|仅微调|2/12|0/12|1/4|0/12|
|仅 RAG|7/12|7/12|4/4|12/12|
|微调 + RAG|4/12|8/12|4/4|12/12|

检索文档 Recall@1、Recall@3 均为 12/12；4 组追问均触发历史补全且命中文档。这里评价的是文档命中，不是段落答案充分性。

两种 RAG 模式经过摘录保底后的关键点初筛均为 11/12。这不能写成“模型准确率 91.7%”。所有 12 道可答题均触发了保底；原始模型质量尚未通过独立验收。当前逐字来源检查偏保守，正确改写也可能被替换。有效引用编号只代表段落存在，不证明语义支持或医学正确。

## 文件与复现

- 项目代码：本仓库根目录。
- 大文件全部在 `$MEDLLM_HOME`：基础模型在 `models`，LoRA 在 `runs\evidence-lf-v2`，合并模型在 `merged\evidence-lf-v2-merged`，GGUF 在 `gguf`，llama.cpp 仓库与二进制在 `llama.cpp` 与 `bin\llama-b11681`，原文、索引与完整评测在 `rag`。
- 冻结试题：`$MEDLLM_HOME\rag\evaluation-cases.json`；四组逐题原始结果：`ablation-results.json`；汇总：`evaluation-summary.json`。
- 本轮 llama.cpp 验收：`$MEDLLM_HOME\rag\llamacpp-alignment-results.json`、`llamacpp-alignment-summary.json`、`user-acceptance-llamacpp\results.json`；构建日志在 `$MEDLLM_HOME\logs`。
- 交付压缩包（应用代码、LoRA 适配器、配置与报告，不含大型基础模型）保存在 `$MEDLLM_HOME\deliverables`。
- 离线运行已有索引即可；重新获取原文运行 `corpus.py`，重建/更新索引由检索器自动处理，完整重测运行 `evaluate_rag.py`。评测会占用 GPU，先停止问答服务。

## 已验证与边界

63 项自动测试通过（本机 2 项因重排序权重与 OCR 依赖已就位而跳过；在无 gold 与语料的空工作目录下另有 6 项跳过），覆盖解析、引用编号校验、多轮会话、取消、过期会话、上传授权、跨站写入限制、llama.cpp 后端契约（流式、语法载荷、think 剥离、取消、服务不可达）、工作目录映射、候选范围 / 重排序 / OCR / 检索阈值四个开关与截断顺序、上下文超限裁剪、指标方向与金标准完整性。实际服务已验证检索、两轮生成、引用段落、清空会话、OpenAPI、Markdown 上传入库与回查，`RAG_CANDIDATE_SCOPE` / `RAG_RERANKER` 两个开关切换后的真实问答，以及**扫描件 PDF 的真实上传**（pypdf 抽 0 字符 → OCR 得 502 字 → 入库 1 段且 `ocr=true` → 提问命中并引用该段）。桌面页面、引用弹窗及 390 像素宽度已验收（页面宽度与内容宽度均为 390）。TXT/MD/HTML/文本 PDF 解析已实现，扫描 PDF 走可选 OCR（`RAG_PDF_OCR=rapidocr`）。

检索使用 BGE-M3 1024 维稠密向量，在 CPU 运行；生成默认由本地 `llama-server`（Q4_K_M GGUF，GPU offload）完成，Transformers + PEFT 4-bit 为回退。追问改写采用显式历史规则；不是额外训练的改写模型。Top-K 后扩展同文档中文导读，原始检索排名另存，避免混淆扩展结果和检索指标。

本阶段已完成 LoRA 合并（CPU、bf16、来自未量化原始权重）、GGUF 转换与 Q4_K_M 量化（llama.cpp b11681，commit 5e03a1ff450c）以及 llama.cpp 推理接入，详见 `LLAMACPP_GGUF_REPORT.md`（含版本、哈希、显存实测 2.5 GiB、边界翻转的根因定位与回退方式）。仍不能将本演示描述为临床诊疗系统。
